# Security Policy

## Reporting a Vulnerability

Use the repository's GitHub **Security** tab to submit a private vulnerability report when private vulnerability reporting is available.

Do not post cookies, credentials, private Feishu links, private document content, access tokens, or unredacted runtime logs in a public issue. If private reporting is unavailable, open a public issue containing only a minimal non-sensitive description and request a private contact channel.

## Supported Version

Security fixes are applied to the latest published version. Users of an unpacked extension should replace the local files with the latest release, reload the extension in `chrome://extensions`, and refresh open target pages.

## Scope

Useful reports include unsafe URL handling, unintended network transmission, unauthorized page access, ZIP path problems, or exposure of sensitive content beyond the user-requested export.
